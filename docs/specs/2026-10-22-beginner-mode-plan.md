## 0. 一页结论

终局由四件事构成：

1. **一个入口**：首页不再是目录，而是 6 个"我想解决…"的任务卡；29 个面板整体下沉为「参考手册」。
2. **一个开关**：新手模式（默认）/ 专家模式，同一份数据、同一套 API，只切换呈现层级；专家模式保留全部现有能力。
3. **一条管线**：文案、阈值、术语、任务定义全部**数据化**进 `DATA`，构建期做 lint 与门禁，禁止在渲染层写死结论。
4. **一个兜底**：离线时任务页仍能用构建期算好的 3 组预设快照演示，不出现空白页。

数字基线：**6 个任务页 + 29 个参考面板 + 40 条术语 + 8 类结论规则**；产物 `index.html` ≤ 700 KB；服务端 0 改动；总量 **35 人日 / 7 周**（1 人 7 周，2 人约 4 周）。

## 1. 背景：问题不在"文案难"，在"没有分层"

### 1.1 现状量化

| 观测点 | 现状 | 位置 |
| --- | --- | --- |
| 首屏主张 | "25 个子模块、1284 条导出全部纳入" | `DATA.panels[0].lead` |
| 顶栏信息 | 覆盖率 100%、面板数据 29/29、colour 版本 | `index.template.html:208-212` |
| 导航分组 | 8 组，原样沿用库的子模块划分（colorimetry / difference / models…） | `DATA.groups` |
| 术语解释 | 无术语浮层/术语表；设计文档只约定"术语保留英文原名" | 全库无 `glossary`/`tooltip` 实现 |
| 颜色输入 | 文本框手打 `#3B82F6, #E9C46A`，标签"逗号分隔，≤12" | `LIVE.convert.fields` |
| 参数选择 | 14 种 ΔE 平铺下拉，无推荐、无说明 | `LIVE["delta-e"].fields` |
| 结果精度 | 表格默认 4 位小数；矩阵只上色不给判断 | `fixed(...,4)`、`renderBlock("matrix")` |
| 计算触发 | 改完参数必须点「调用 API」 | `wirePanel` → `#run-live` |
| 首屏阻塞 | 先 `apiProbe()` 再渲染，健康检查慢则白屏 | `index.template.html:1251` |
| 产物体积 | `index.html` 407 KB（其中 DATA 302 KB） | `.tmp` 实测 |

### 1.2 三个新手任务，现在都走不通

| 用户想做的事 | 现在的路径 | 断点 |
| --- | --- | --- |
| 我这套配色，色弱的人能分清吗 | 导航找「色觉障碍模拟」（面板 18）→ 手打颜色列表 → 点调用 API → 看 7 个块 | 找不到入口；不知道"相邻 ΔE<3 就是分不清"；矩阵无结论 |
| 这两个颜色差多少 | 找「ΔE 全家桶」（面板 05）→ 默认 CIE 2000 → 11.2 | 没有"11.2 算不算明显"的判断；4 位小数无意义 |
| 这个颜色屏幕显示得出来吗 | 面板 09/10 看面积表与体积 | 面积/体积回答不了"能不能显示"；而且这个概念本身要纠正（§8.4） |

### 1.3 根因

1. **入口按库的结构组织**，用户按问题找东西；
2. **文案写给同行**，默认读者知道 ΔE、CCT、白点是什么；
3. **数字没有判据**，只给测量值不给结论；
4. **技术噪音前置**，端点、JSON、覆盖率、阶段号挤在首屏。

结论：不是把 29 页写得更浅，而是**加一层"问题 → 操作 → 结论"的外壳，把参考手册完整保留在下一层**。

## 2. 终局定义

### 2.1 一句话定位

> **把颜色讲清楚**：用 30 秒回答一个具体的颜色问题，并告诉你"差多少、为什么、下一步怎么办"；想深究时，29 个专业面板一步可达。

### 2.2 四层信息架构

```
┌──────────────────────────────────────────────────────────────┐
│ L0 全局层   模式开关 · 搜索（任务/术语/面板）· 术语浮层 · 导览   │
├──────────────────────────────────────────────────────────────┤
│ L1 任务层   首页（6 张任务卡）→ 任务页（问题/操作/结论/延伸）      │
├──────────────────────────────────────────────────────────────┤
│ L2 工具层   任务页的"更多参数"（同一引擎，展开即专业控件）          │
├──────────────────────────────────────────────────────────────┤
│ L3 参考层   29 个面板：人话头 + 结论 + 原理折叠（新手视图）        │
│             专家模式：原始 lead / 4 位小数 / JSON / API 页脚      │
└──────────────────────────────────────────────────────────────┘
```

关键点：**L1/L2/L3 共用同一份 `DATA` 与同一批 API**，不存在第二套算法或第二份数据。

### 2.3 设计原则

| # | 原则 | 可检验的落地方式 |
| --- | --- | --- |
| P1 | 先现象，后原理 | 每个面板前 3 句话不出现禁用术语（§5.5） |
| P2 | 每个数字都有判据 | 数值块必须声明 `verdict` 规则，否则渲染"怎么读"帮助文本 |
| P3 | 默认给推荐，专家可下钻 | 方法选择默认 1 个推荐项，其余折叠 |
| P4 | 颜色先给色块，再给数值 | 所有结果区首屏必须出现色块或色带 |
| P5 | 一次只问一个问题 | 任务页 H1 是一个问句，且只有一个主操作 |
| P6 | 技术信息可查不可挡路 | API/JSON/精度说明只出现在「原理」或专家模式 |
| P7 | 离线也能看懂 | 任务页 3 组预设快照，离线可切换 |
| P8 | 不改专业内容 | 原 `lead`、表格、端点说明在专家模式逐字保留 |

### 2.4 非目标

- 不做账号、不做云端保存、不做多语言（中文优先，术语保留英文原名）；
- 不做色彩管理系统，不做 CMYK 打样、不做 ICC 流程（现有面板只做展示）；
- 不引入前端框架、npm、打包器（G3：零前端工具链）；
- 不删除、不改写任何专业结论与数值口径；
- 不做 SEO 预渲染（hash 路由维持现状）。

### 3.2 路由规范

| 规则 | 说明 |
| --- | --- |
| 主路由 | hash 路由，形态 `#/<类型>/<id>`，便于静态托管与 `file://` |
| 旧链接兼容 | 裸 hash `#chromaticity` 一律 `location.replace('#/ref/chromaticity')`，不产生历史记录 |
| 默认路由 | 空 hash → `#/`；未知 id → 首页并 toast「没找到这一页」 |
| 参数 | 任务状态用 query：`?colors=%23AABBCC,%23DDEEFF&space=Oklab`；与 `advanced` 同级 |
| 模式 | `?mode=expert` 优先，其次 `localStorage['cd:mode']`，最后默认 `beginner` |
| 滚动 | 路由切换 `scrollTo(0,0)`；同路由仅改 query 不滚顶 |
| 深链 | 所有任务页必须可分享：URL 还原后结果与分享时一致（阈值/算法固定） |

### 3.3 模式定义

| 维度 | 新手模式（默认） | 专家模式 |
| --- | --- | --- |
| 首页 | 任务卡 | 任务卡 + 全站地图 + 覆盖率统计 |
| 导航 | 开始 / 任务 / 参考手册（折叠）/ 术语表 | 同左，参考手册默认展开 |
| 面板头 | `title_plain` + `plain` + `question` | 原 `title` + `lead` + `Panel NN · 阶段` |
| 数值精度 | ΔE 1 位、坐标 2–3 位、色温整数 | 原始 4–6 位 |
| 方法选择 | 推荐 1 项 + 「更多方法」 | 全量平铺 |
| 计算 | 改参数自动算（防抖 250 ms） | 同左，另保留「手动重算」 |
| 结果 | 结论卡 + 精简表（≤8 行）+ 色块 | 全部块 + 矩阵 + JSON trace |
| 页脚 | 「本页数字怎么来的」+ 去专家视图 | API 端点 + `colour` 调用名 |
| 顶栏 chip | 「数字由 colour 0.4.7 计算」/ 离线标识 | + 覆盖率、面板进度 |

模式切换必须在**任意页面**可用，切换后保持当前路由；切换写入 `localStorage`，不写 URL（分享链接默认按 URL 的 `mode` 渲染）。

## 4. 数据模型（构建期）

`DATA` 在现有字段上**只增不改**，旧字段全部保留，保证专家视图与回滚可用。

### 4.1 总览

```js
DATA = {
  lib:     { version, numpy, matplotlib, python },   // 不变
  groups:  [...],                                    // 不变
  panels:  [ Panel ],                                // 每项新增 §4.2 字段
  catalog: {...},                                    // 不变
  stats:   {...},                                    // 不变
  tasks:   [ Task ],                                 // 新增
  glossary:{ [key]: Term },                          // 新增
  verdicts:{ [rule]: RuleSet },                      // 新增
  ui:      { schema: 2 }                          // 新增；刻意不放时间戳，保证构建可复现
}
```

### 4.2 Panel 扩展字段

| 字段 | 类型 | 约束 | 缺失时 |
| --- | --- | --- | --- |
| `title_plain` | string | ≤ 20 字，零禁用术语 | 构建失败 |
| `question` | string | ≤ 30 字，必须是问句（以 `？` 结尾） | 构建失败 |
| `plain` | string | 30–80 字，零禁用术语 | 构建失败 |
| `why` | string | 15–50 字，描述使用场景 | 构建失败 |
| `presets` | Preset[3] | 有实时适配器的面板必须 3 个；静态面板可为 `[]` | 允许空 |
| `verdict` | string \| null | 必须在 `DATA.verdicts` 中存在 | `null` → 渲染"怎么读" |
| `jargon` | string[] | 每项必须在 `DATA.glossary` 中存在 | 允许空 |

```python
# gen/common.py
def panel(pid, group, no, title, lead, blocks, *,          # 原有参数不变
          phase="M1", apis=None, controls=None, footer="",
          title_plain="", question="", plain="", why="",
          presets=None, verdict=None, jargon=None):
    return {..., "title_plain": title_plain, "question": question,
            "plain": plain, "why": why, "presets": presets or [],
            "verdict": verdict, "jargon": jargon or []}
```

`Preset` 的 `state` 必须与对应 `LIVE[panelId].fields` 的 `key` 完全一致（构建期用 `gen/manifest.py` 的 `LIVE_PANEL_IDS` 做集合校验；运行期再校验一次并 `console.error`）。

## 5. 文案规范

### 5.1 每个页面固定四段式

| 段 | 内容 | 长度 | 出现在 |
| --- | --- | --- | --- |
| ① 问题 | 一个具体的人会问出口的句子 | ≤ 30 字 | H1 |
| ② 做法 | 动宾结构，说明 3 步内怎么操作 | ≤ 40 字 | 副标题 |
| ③ 结论 | 人话判断 + 关键数字 + 下一步 | 40–80 字 | 结论卡 |
| ④ 原理 | 术语原名、公式选择理由、完整数据 | 不限 | 「原理与专业参数」折叠区 |

**任务页**是把 ③ 放大、④ 收起的形态；**参考面板**是把 ④ 保留、① 换成人话标题的形态。两者不重复写事实，只重复调用同一份数据。

### 5.2 术语规则

1. 首次出现：中文名 + 括号原文，如「色差（ΔE）」，并挂术语浮层；
2. 同一段内不重复挂；
3. 标题、任务卡、按钮文案**不允许**出现未解释术语；
4. 专业原名只出现在：术语表、`title`（专家视图）、`原理` 折叠区、专家模式；
5. 全站术语由 `DATA.glossary` 单一来源提供，改一处全站生效。

### 5.3 数字与结论档位

| 量 | 展示精度 | 档位规则（产品口径） |
| --- | --- | --- |
| ΔE | 1 位小数 | <1 几乎看不出；1–2 仔细看能发现；2–5 看得出来；5–10 明显；>10 完全不同 |
| 色温 CCT | 整数 + K | <3300 暖黄；3300–5300 中性；5300–7000 日光；>7000 偏冷 |
| 坐标 xy / u′v′ | 2–3 位 | 不做档位，仅给位置与色块 |
| 色域面积 | 2 位 + ×sRGB | 不做档位，只做相对比较 |
| 激发纯度 | 0–1，展示为百分比 | <15% 接近灰白；15–35% 偏柔和；35–60% 明显有色；60–80% 鲜艳；>80% 非常鲜艳（产品口径） |
| 渐变均匀度 | 2 位（max/min 比） | <1.5 均匀；1.5–2.5 轻微不均；>2.5 明显不均 |
| 色弱可区分性 | 1 位 ΔE | <3 视为分不清（与 `core/cvd.py` 的 `INDISTINGUISHABLE_DELTA_E` 对齐） |
| 显色指数 | 整数 | 不合并成单一档位：Ra / Qa / Rf / Rg 并列展示，提示"四个口径可能打架" |
| 色号 | 原样 + 色块 | 不做档位 |

免责说明（必须出现在「原理」折叠区首行）：
> 档位是经验参考，不是标准强制值；换算法、换观察条件，数字都会变。

### 5.6 改写样例（8 个）

**00 概览 → 首页**
> 现在：颜色不是三个字节，而是「物理量 + 观察条件 + 感知模型」。这个演示把 colour-science 0.4.7 的 25 个子模块、1284 条导出全部纳入……
>
> 终局：**把颜色讲清楚。** 两个颜色看着一样、数值却不同？屏幕上的颜色印不出来？挑一个问题，30 秒拿到结论。
> （小字）所有数字由 colour-science 0.4.7 真实计算。

**01 颜色转换与换算图**
> 现在：一支颜色在 14 个核心坐标系里的坐标，外加通过 `colour.convert()` 换算图可达的 24 个空间——106 个节点之间任意跳转……
>
> 终局：**一个颜色，能写成多少种样子？** 同一个蓝，在设计师的 HEX、印刷的 Lab、视频的 YCbCr 里分别是多少。粘贴一个色号就能看到全部写法。
> 原理：14 个核心空间 + 换算图可达的 24 个空间，路径由最短路径给出。

**05 ΔE**
> 现在：同一对颜色，14 个公式给出 14 个数字。ΔE 2000 是工业默认……
>
> 终局：**这两个颜色，差得明显吗？** 选两个颜色，得到一个能直接用的判断：几乎看不出 / 看得出来 / 完全不同。
> 原理：14 种算法并列，CIE 2000 是工业默认；换算法数字会变，但方向通常一致。

**06 渐变**
> 现在：把同一组端点丢进 7 个空间做线性插值：数学上都是「直线」，观感上差别很大……
>
> 终局：**渐变为什么中间发灰？** 同一个蓝到黄，在 sRGB 里补会发灰，在 Oklab 里补更顺。三条渐变色带并排，差别一眼可见。

**09 色度图**
> 现在：三种色度图描述的是同一件事，只是「均匀程度」不同……
>
> 终局：**100% sRGB 的屏幕，到底能显示多少颜色？** 三个色域三角形叠在一张图上，多出来的部分一眼可见；顺便纠正一个常见误解：单个色号一定显示得出来，显示不出来的是超出设备能力的颜色。

**18 色觉障碍**
> 现在：约 8% 的男性有某种色觉障碍。Machado 2009 用一个与严重程度相关的矩阵……
>
> 终局：**这套配色，红绿色弱的人能分清吗？** 贴上你的颜色，切到红色盲，看哪几块糊成一片，并给出替换建议。

**21 记号与解析**
> 现在：「5R 5/12」「tomato」「#3B82F6」「Kelvin 6500」——同一件事有四种写法……
>
> 终局：**别人发你一个色号，你能看懂吗？** 把 `#3B82F6`、`tomato`、`5R 5/12` 粘进来，这里翻译成同一套坐标。

**28 API 控制台**
> 现在：正式版所有能力都是 JSON API，前端只是它的第一个消费者……
>
> 终局：**想把颜色计算接进自己的程序？** 30 个接口一览，复制即用；不需要装 colour-science 也能先看返回长什么样。

### 6.1 新手模式默认行为

| 场景 | 行为 |
| --- | --- |
| 打开任务页 | 用预设立即渲染结论卡（不等网络），再后台探测 API |

| 专家模式 | 恢复「调用 API」按钮与 JSON trace，保留手动重算 |

### 6.2 颜色输入组件

结构：

```
[色块] #3B82F6  × | [色块] #E9C46A  × | [ + 添加颜色 ]
预设： 几乎一样 · 轻微偏色 · 完全不同
[ 吸管 ]（支持时显示）  [ 粘贴色号 __________ ]
```

规则：
- 色块 28×28，圆角 6，边框 `rgba(0,0,0,.08)`，点击打开原生取色器；
- HEX 文本可编辑，失焦规范化（大写、补 `#`）；
- 客户端解析：`#RGB` / `#RRGGBB` / `rgb()` / `hsl()` / CSS 关键字，用 canvas `fillStyle` 归一化，**不合法不请求 API**，就地提示「只认识 #RRGGBB、rgb(…) 或颜色名」；
- `EyeDropper` 存在时显示"吸管"，不支持则隐藏（不做降级提示）；
- 数量约束由 task/panel 声明：少于下限提示「至少 2 个颜色」，超过上限禁用「添加」并提示「最多 12 个」；
- 键盘：`Enter` 确认输入，`Backspace`（空输入框）删除最后一个色块，`×` 可由 `Tab` 聚焦；
- 每个色块 `aria-label="颜色 1，#3B82F6，删除"`；
- 粘贴区支持一次粘贴多个（逗号/换行/空格分隔），自动去重。

### 6.3 参数选择

- `kind: "method"`：默认只显示推荐项（radio），下方「更多方法（13）」`details` 展开；
- 每个选项一句说明（≤ 16 字），如「CIE 2000 · 工业默认，最常用」；
- 不常见的数值参数（如 `L_A`）收进「高级参数」，默认值加说明「一般不用改」；
- 参数与结论联动：改算法后结论卡更新，并保留一行「换算法前：ΔE 11.2 → 现在：ΔE 9.8」，避免用户困惑。

### 6.4 自动计算状态机

```
idle ──input(250ms)──▶ debouncing ──▶ loading ──▶ success
                          ▲              │            │
                          └──input───────┘            │
                                         └─error──────┘
离线：offline（控件禁用，预设可切快照）
```

实现要点：
- `AbortController` 每次请求新建，`fetch` 超时 8 s；
- 请求序号 `seq`，只有 `seq === latest` 的响应能写 DOM；
- 成功后写 `history.replaceState` 更新 query（不新增历史条目）；
- 错误映射：`value_error` 原样展示（服务端已是人话）；`too_large` → 「颜色太多，最多 12 个」；`internal_error` → 「计算出了点问题，重试一次」；网络错误 → 「连不上本地服务，检查是否已启动」。

### 6.5 结论卡

固定结构（顺序不可变）：

```
┌──────────────────────────────────────────────┐
│ [色块A] [色块B]        ΔE 11.2 · 明显不同      │  ← 大号判断 + 关键数字
│ 一眼就是两个颜色。并排看差异很明显。            │  ← 一句人话
│ 计算口径：CIE 2000 · sRGB · D65                │  ← 小字，可展开术语
│ [换个算法看看]  [复制结论]  [去参考页看全部数据] │
└──────────────────────────────────────────────┘
```

- `tone` 三档颜色：`ok`（绿）/ `warn`（琥珀）/ `bad`（红），只用浅色背景，不改变文字主色；
- 结论卡必须由 `verdicts` 数据 + 实际 payload 生成，**禁止静态文案**；
- 数字格式统一走 `fmt.byKind(kind, value)`，禁止各页自己 `toFixed`。

### 6.6 对比模式

- 任务页默认给「并排对比」：左右两块等宽色块 + 中间 ΔE；
- 三个以上颜色：网格排列，命中 `min_adjacent_delta_e` 的一对加描边 + 「这两块最像」标记；
- 参考面板保留表格，但顶部加一行「结论」摘要，折叠后可见。

### 6.7 空 / 错 / 离线态

| 状态 | 文案 | 动作 |

## 7. 六个任务页规格

通用结构：面包屑 → 问句 H1 → 一句做法 + 预计时间 → 预设行 → 输入 → 结论卡 → 「换个角度」→ 「背后发生了什么」折叠 → 「去参考页看全部参数」→ 分享区。

### 7.1 `purity` 这个颜色，够鲜艳吗？

| 项 | 规格 |
| --- | --- |
| 输入 | 1–5 个颜色，默认 3 个（品牌蓝 `#3B82F6`、柔灰蓝 `#9DB2C6`、纯红 `#FF0000`）；光源默认 `D65`，可选 `A` / `FL2` |
| 步骤 | 选颜色 → 看每个颜色的鲜艳度 → 展开「为什么」 |
| 接口 | `POST /api/v1/chroma {colors, illuminant}` |
| 结论逻辑 | 取 `rows[].excitation_purity`（0–1）走 `purity` 档位；`dominant_wavelength` 为 `null` 时改说「接近白/灰，没有明确主色」 |
| 呈现 | 结论卡 + 每个颜色一行（色块 / 纯度百分比 / 最接近的单色光波长 / 一句解释） |
| 边界 | 纯度依赖光源白点，换光源数字会变——页面显式给光源选择器并在原理区说明；`excitation_purity` 与 `colorimetric_purity` 并列展示，结论只用前者 |
| 延伸 | 参考页 `#/ref/chroma`、`#/ref/chromaticity` |

> 为什么不做「这个颜色屏幕显示得出来吗」：本接口的 `inside` 判定对任何 HEX 输入恒为真（输入本身就是 sRGB 编码值）。这属于用户心智模型错误，正确做法是在面板 09 纠正，而不是做一个永远回答"能"的任务（见 §8.4）。

### 7.2 `delta-e` 这两个颜色，差得明显吗？

| 项 | 规格 |
| --- | --- |
| 输入 | 2–12 个颜色，默认 2 个；方法默认 `CIE 2000` |
| 步骤 | 选两个颜色 → 直接看结论 → 想细看再展开矩阵 |
| 接口 | `POST /api/v1/delta-e {colors, method}` |
| 结论逻辑 | 2 个颜色：直接用 `matrix[0][1]` 走 `deltaE` 档位；>2 个：先给「最像的一对」「最不像的一对」，再给全部两两（折叠） |
| 呈现 | 并排色块 + ΔE + 档位句 + 「换个算法看看」（切换后保留前后对比一行） |
| 边界 | <2 个颜色不请求；非有限值（`warning: undefined`）→ 「这两个颜色超出了该算法的适用范围，换 CIE 2000 试试」 |
| 复制结论 | `【色差】#3B82F6 与 #E9C46A 的 CIE 2000 色差为 11.2；按经验属于"明显不同"。` |
| 延伸 | 参考页 `#/ref/delta-e` |

### 7.3 `gradient` 渐变为什么中间发灰？

| 项 | 规格 |
| --- | --- |
| 输入 | 起点、终点、3 个对比空间（固定 `Oklab` / `CIE Lab` / `sRGB`）、步数默认 11 |
| 步骤 | 选两端颜色 → 三条色带并排 → 看哪条最均匀 |
| 接口 | 3 次 `POST /api/v1/gradient`（并发），相同 `steps` |
| 结论逻辑 | 比较 `uniformity.ratio`（max/min 相邻 ΔE）：最小者为「最均匀」；若 sRGB 的 ratio 是 Oklab 的 2 倍以上，输出「sRGB 中段被压缩，所以看起来发灰」 |
| 呈现 | 三条色带（标注空间 + ratio）+ 相邻 ΔE 折线（可切换空间）+ 结论卡 |
| 边界 | 步数 2–101；某空间不可用 → 该条显示「这个空间算不了」不影响其余 |
| 延伸 | 参考页 `#/ref/gradient` |

### 7.4 `cvd` 色弱的人能分清这套配色吗？

| 项 | 规格 |
| --- | --- |
| 输入 | 2–12 个颜色（调色板，按顺序）；三类色觉一起算，默认展开「绿色弱/绿色盲」，严重程度 100% |
| 步骤 | 贴配色 → 切换三类色觉 → 看哪几块糊在一起 |
| 接口 | 3 次 `POST /api/v1/cvd`（`Deuteranomaly` / `Protanomaly` / `Tritanomaly`，`severity=1.0`） |
| 结论逻辑 | 取 `metrics.min_adjacent_delta_e`，<3 → 判定「分不清」；标出具体相邻对（第 i / i+1 个），给替换建议（提高明度差 / 换深蓝 / 加纹理） |
| 呈现 | 原色带 + 三类模拟色带（上下对齐）+ 结论卡 + 「哪两块最像」 |
| 边界 | 用相邻可区分性作代理指标（与 `core/cvd.py` 一致），文案说明「这里看相邻两块，完整两两矩阵在参考页」；调色板顺序会影响"相邻"，允许拖拽排序（终局包含） |
| 延伸 | 参考页 `#/ref/cvd` |

### 7.5 `light` 换一盏灯，颜色还一样吗？

| 项 | 规格 |
| --- | --- |
| 输入 | 1 个颜色 + 源光源（默认 A 白炽灯）+ 目标光源（默认 D65 日光）；可选第二组对比 |
| 步骤 | 选颜色 → 选"现在"和"换到" → 看前后并排 |
| 接口 | `POST /api/v1/adapt {colors, source, target, methods:["Bradford"]}`；可选 `POST /api/v1/temperature` 显示色温 |
| 结论逻辑 | 用返回的 `delta_e`（原色 vs 适应后）走 `deltaE` 档位；同时判断 `hex` 是否被裁切（超出 sRGB）→ 追加「这个颜色超出屏幕范围，显示的是近似色」 |
| 呈现 | 前后两块色块 + ΔE + 一句解释 + 色温小标签（如 `A ≈ 2856 K`） |
| 边界 | 源=目标 → 前端直接提示「同一盏灯，结果不会变」且不发请求（服务端会拒绝同白点）；方法默认 Bradford，其余折叠 |
| 延伸 | 参考页 `#/ref/adaptation`、`#/ref/temperature` |

### 7.6 `notation` 这个色号，换成别的写法是多少？

| 项 | 规格 |
| --- | --- |
| 输入 | 一个值，接受 HEX / `rgb()` / CSS 关键字 / Munsell（如 `5R 5/12`）；默认 `#3B82F6` |
| 步骤 | 粘贴 → 看同一颜色的多种写法 → 复制 |
| 接口 | 客户端先解析 CSS 颜色；HEX 走 `POST /api/v1/notation {hex}`；Munsell 走 `{munsell}`；关键字走 `{keyword}` |
| 结论逻辑 | 输出等价卡：HEX / RGB / Lab / LCh / Munsell（能转时）/ CSS 名（有则给）；每项可单独复制 |
| 呈现 | 大色块 + 4–6 行等价写法 + 「复制全部」 |
| 边界 | Munsell 解析失败 → 「Munsell 写法像 5R 5/12（色相 明度/彩度），检查一下空格」；颜色名不在 CSS 列表 → 提示可用列表前 10 个 |
| 延伸 | 参考页 `#/ref/notation` |

### 8.4 必须写进页面的四个口径陷阱

新手文案最容易犯的错，是为了"好懂"而承诺工具其实做不到的事。以下四条必须在页面里显式说明：

| # | 陷阱 | 处理 |
| --- | --- | --- |
| 1 | 任何 HEX 输入都落在 sRGB 内，`inside` 恒为真 | 不做"这个颜色显示不出来"的任务；面板 09 改为讲"设备能显示多少颜色"，并加一句「单个色号一定显示得出来」 |
| 2 | 色弱页用"相邻两色"作可区分性代理，不是完整两两矩阵 | 结论卡写「这里看相邻两块」，完整矩阵放参考页 |
| 3 | 纯度依赖光源白点，换光源数字会变 | 提供光源选择器；结论卡标注当前光源；原理区说明"不是 HSL 饱和度" |
| 4 | 色适应结果超出 sRGB 时会被裁到 0–1，hex 只是近似色 | 结论卡追加「超出屏幕范围，显示的是近似色」 |

## 9. 前端技术方案

### 9.1 源码结构（产物仍是单文件）

```
docs/prototype/
├── index.template.html        # 外壳 + CSS + /*__UI__*/ + /*__DATA__*/
├── ui/
│   ├── core.js                # 工具、格式化、路由、模式、存储
│   ├── glossary.js            # 术语高亮与浮层
│   ├── blocks.js              # 通用块渲染（table/matrix/kv/strips/...）
│   ├── charts.js              # SVG 折线/散点/柱
│   ├── components.js          # 颜色输入、方法选择、结论卡、预设、步骤
│   ├── adapters.js            # M2 面板适配器（01/02/05/09/10/11/14/18）
│   ├── adapters-late.js       # M3/M4 面板适配器（19–28、03/04/07）
│   ├── live.js                # API 探测/调用 + 实时结果运行器
│   ├── panels.js              # 参考面板视图（含新手过渡说明）
│   ├── tasks.js               # 6 个任务页视图
│   └── app.js                 # 启动、导航、搜索、导览
├── gen/
│   ├── common.py              # panel() 扩展 + 文案校验
│   ├── manifest.py            # 面板/任务/实时面板 id 清单（单一来源）
│   ├── tasks.py               # 任务元数据（纯数据，无 colour 依赖）
│   ├── glossary.py            # 40 条术语（纯数据）
│   └── verdicts.py            # 阈值与结论文案（纯数据）
└── build_prototype.py         # --tasks / --merge，拼接 + 门禁
```

约束：
- 不引入 npm / node / 打包器；`--merge` 只做字符串拼接；
- `ui/*.js` 是普通脚本，按 `UI_FILES` 固定顺序拼接，禁止 `import`/`export`；
- 每个文件 ≤ 400 行，超过就拆；
- JS 内不得出现 `</script>`（拼接后会截断），构建期断言。

### 9.2 构建管线

```bash
# 1) 面板快照（沿用现有三批，低内存）
python docs/prototype/build_prototype.py --batch 1
python docs/prototype/build_prototype.py --batch 2
python docs/prototype/build_prototype.py --panel recovery   # 19–25 逐个
# 2) 任务快照：6 任务 × 3 预设 = 18 次计算，复用 src/colour_demo/core
PYTHONPATH=src python docs/prototype/build_prototype.py --tasks
# 3) 合并 + 门禁 + 写 index.html
PYTHONPATH=src python docs/prototype/build_prototype.py --merge
```

`--tasks` 必须 `from colour_demo.core.delta_e import delta_e_matrix` 等**直接复用服务端实现**，保证快照与在线结果同源；禁止在 `gen/` 里重写算法。

`--merge` 步骤：

```python
UI_DIR = HERE / "ui"
UI_FILES = ["core.js", "glossary.js", "blocks.js", "charts.js",
            "components.js", "adapters.js", "adapters-late.js",
            "live.js", "panels.js", "tasks.js", "app.js"]
ui = "\n\n".join((UI_DIR / name).read_text(encoding="utf-8") for name in UI_FILES)
assert "</script>" not in ui, "UI 源码里不能出现 </script>"
payload = json.dumps(data, ensure_ascii=False, separators=(",", ":"))
html = TEMPLATE.replace("/*__UI__*/", ui).replace("/*__DATA__*/", payload)
assert len(html.encode()) <= 700 * 1024, "产物超过 700 KB"
```

### 9.3 渲染管线（去掉首屏阻塞）

```
1. 解析 URL（mode / route / query）
2. 用 DATA 立即渲染外壳 + 当前路由的静态结果（含任务预设快照）
3. 首帧后异步探测 /api/v1/health（1.5 s 超时）
4. 在线 → 启用控件、按需现算；离线 → 提示条 + 禁用控件
5. 路由变化 → 只重渲染 main 区域
```

与现状的差异：**不再 `apiProbe().finally(activate)`**，health 探测永远不阻塞首帧。

### 9.4 状态与路由

```js
const State = {
  mode: "beginner",          // beginner | expert
  route: { type: "home" | "task" | "ref" | "glossary" | "tour", id, query },
  live: { checked, ok, version, whitelist },
  taskState: {},             // 每个任务页独立，切换回来保留
};
```

- 路由解析纯函数 `parseHash(hash)`，单测友好；
- `applyRoute()` 只改 `main`，导航高亮单独更新；
- 任务状态 → query 的序列化必须稳定（键排序、颜色大写），保证链接可复现。

### 9.5 术语高亮实现

```js
// 只处理 .js-prose 容器；最长匹配；跳过 code/pre/a/button
function annotateTerms(root) {
  const walker = document.createTreeWalker(root, NodeFilter.SHOW_TEXT, {
    acceptNode: (n) => n.parentElement.closest("code,pre,a,button,.no-terms")
      ? NodeFilter.FILTER_REJECT : NodeFilter.FILTER_ACCEPT,
  });
  // 收集文本节点 → 一次性构建匹配 → 用 Range 替换，避免反复触发重排
}
```

约束：每段文本每个术语最多 1 次；不处理长度 < 2 的别名；浮层内容全部来自 `DATA.glossary`。

- 审校需要 1 名色彩专业背景评审人，至少投入 3 人日（不占开发工时，但必须排进日历）。

### 12.4 开关与发布

| 控制 | 方式 |
| --- | --- |
| 默认模式 | `ui/core.js` 的 `DEFAULT_MODE`，改一行即可回退 |

## 13. 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 文案"翻译腔"，仍然看不懂 | 中 | 高 | 5 人可用性测试前置到 M2；每条结论必须由数据规则生成，禁止手写 |
| 阈值口径被质疑（ΔE 2/5/10） | 中 | 中 | 明确标注"经验参考，非标准强制"；原理区给算法原名；专业评审签字 |
| 双模式维护成本翻倍 | 中 | 中 | 单一数据源 + 渲染分支；禁止复制事实文本；W6 统一审校 |
| 专家用户反感 | 低 | 中 | 专家模式一键、记忆偏好、URL 可强制；29 面板逐字保留 |
| 产物体积膨胀 | 中 | 低 | 700 KB 硬门禁；术语与任务数据压缩键名 |
| 离线快照与在线结果不一致 | 低 | 高 | 快照直接调用 `core/*` 同实现；发布前抽样比对 hex/ΔE |
| 旧链接失效 | 低 | 中 | 裸 hash 重定向 + G9 断言 + 回归清单 |

回滚步骤：把 `DEFAULT_MODE` 改为 `"expert"` → 重新 `--merge` → 发布。数据字段保留，无需回滚数据。

| `transfer-function` | 传递函数 | 文件里的数字和实际亮度之间的换算曲线。 |
| `lut` | 3D LUT | 一张"输入颜色 → 输出颜色"的查找表，调色常用。 |
| `munsell` | Munsell | 用"色相 明度/彩度"描述颜色的经典体系，如 5R 5/12。 |
| `cvd` | 色觉障碍 | 分辨某些颜色困难，最常见的是红绿型。 |
| `jnd` | 最小可觉差 | 人眼刚好能察觉的最小差别，ΔE 约等于 1。 |
| `csf` | 对比敏感度 | 不同粗细的图案，人眼能看出多小的对比。 |
| `hk-effect` | H-K 效应 | 鲜艳的颜色会显得更亮。 |
| `macadam` | MacAdam 椭圆 | 图上同一个"感觉一样"的范围，椭圆越大越不敏感。 |

| `palette` | 调色板 | 一组搭配使用的颜色。 |
| `wcag-contrast` | 对比度 | 文字和背景的亮度差，网页无障碍有明确门槛。 |

| `gamut-mapping` | 色域映射 | 把超出设备范围的颜色"压缩"进可显示范围。 |
| `hue-angle` | 色相角 | 在 Lab/LCh 里用角度表示色相，0° 附近是红。 |
| `observer` | 标准观察者 | 用平均人眼数据定义的"人眼模型"，常用 2° 和 10°。 |
